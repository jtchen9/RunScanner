# Robot Mobility Calibration and Preflight Runbook

This runbook covers robots using the **balanced timed drivetrain v2** software, all-metal TT motors, and the original low-cost Mecanum wheels.

Run all commands from:

```bash
cd /opt/_RunScanner
```

## 1. Before calibration

### Hardware inspection

1. Use four fresh motors; do not use motors previously subjected to destructive torque testing.
2. Confirm the four wheels form the correct Mecanum **X pattern**.
3. Tighten all wheel-to-shaft screws and motor/chassis fasteners.
4. Confirm every wheel contacts the floor and turns freely.
5. Check motor-wire polarity, connectors, and strain relief.
6. Turn on the large motor battery.
7. Provide a clear flat-floor path and prepare the bump/ramp area when bump calibration is required.

### I2C check

```bash
i2cdetect -y 1
```

Both addresses must appear:

- `10`: motor HAT
- `68`: IMU/gyro

Do not continue if either address is missing.

### Display the active calibration without movement

```bash
python3 TestGyro/robot_mobility_calibrate_v2.py --check
```

Confirm that the robot name is correct and, for an already calibrated upgraded robot, that the active model is:

```text
balanced_timed_v2
```

This command does not move the robot or alter calibration.

## 2. Run calibration

Start the interactive calibrator:

```bash
python3 TestGyro/robot_mobility_calibrate_v2.py
```

The program asks whether to calibrate each section. Answer `n` to skip a section and preserve its existing production value. Calibration results are written to production only after the final confirmation.

### Section 1 — Stationary gyro bias

Prompt:

```text
Calibrate stationary gyro bias? [y/N]
```

If selected:

1. Keep the robot completely stationary.
2. The program takes three measurements.
3. Do not touch the robot until all three finish.
4. The between-test spread must be no more than `0.10 deg/s`; otherwise the section fails.

### Section 2 — Flat-floor forward PWM balance

Prompt:

```text
Calibrate flat-floor forward PWM balance? [y/N]
```

If selected:

1. Enter right/M1 and left/M2 PWM values.
2. Mark the starting position and heading.
3. Run the 5-second trial.
4. Observe smoothness, heading, and lateral displacement.
5. Adjust the balance and repeat until the robot travels smoothly and nearly straight, without visible zig-zag.
6. Accept the balance only when satisfactory.

Alpha's established starting reference is right/left PWM `30/29`. Other robots must be calibrated individually; do not copy Alpha's measured result automatically.

### Section 3 — Flat-floor distance timing

Prompt:

```text
Calibrate flat-floor forward distance timing? [y/N]
```

If selected:

1. Mark an identical starting point for each trial.
2. The program runs two 9-second forward trials.
3. Measure each forward distance in **centimetres** and enter it.
4. The program calculates seconds per metre.
5. It then runs a 1.0-m verification.
6. Measure and enter the verification distance in centimetres.
7. Accept only if the result is repeatable and the motion remains smooth.

### Section 4 — Turning

Prompt:

```text
Calibrate turning? [y/N]
```

If selected:

1. Choose the turn PWM. `30` is the established reference for Alpha.
2. Mark the starting heading.
3. Run ten zero-margin LEFT/CCW 90-degree turns.
4. Enter the **total cumulative physical error**:
   - positive = overshoot
   - negative = undershoot
5. Mark the heading again and repeat for ten RIGHT/CW turns.
6. The program divides each cumulative error by ten to calculate the directional stop margin.
7. Run the compensated ten-turn CCW and CW verification tests.
8. Enter the compensated cumulative physical errors and accept only if turning is smooth and repeatable.

During every turn, all four wheels should engage immediately. Reject the result if a wheel stalls, the robot pivots around a stuck wheel, or an abnormal sound appears.

### Section 5 — Bump crossing

Prompt:

```text
Calibrate bump crossing? [y/N]
```

If selected:

1. Enter separate right/M1 and left/M2 PWM values for both directions.
2. The program performs the tests in this order so the robot does not needlessly repeat one direction:
   1. `+Y` inner-to-outer 12-second timing trial
   2. `-Y` outer-to-inner 12-second timing trial
   3. `+Y` inner-to-outer calibrated 2.0-m verification
   4. `-Y` outer-to-inner calibrated 2.0-m verification
3. After each timing trial, confirm the robot cleared the ramp without stalling and enter the measured distance in centimetres.
4. After each verification, confirm it cleared without stalling or manual assistance and enter the measured distance.
5. Reject any trial that stalls; do not derive timing from an incomplete crossing.

Alpha's established bump reference is right/left PWM `40/39`. Its accepted crossings were approximately 2.0 m. Each robot still requires its own calibration.

### Final write confirmation

At the end, review the printed JSON summary carefully. Only answer `y` to:

```text
Write this calibration to the production registry? [y/N]
```

when every selected section is acceptable.

The calibrator then writes:

- Result record: `/opt/_RunScanner/TestGyro/calibration/drivetrain_v2_result.json`
- Production registry: `/opt/_RunScanner/robot_mobility_calibration.json`

If the final answer is `n`, production calibration is not changed.

### Verify the saved calibration

```bash
python3 TestGyro/robot_mobility_calibrate_v2.py --check
```

Confirm the displayed values match the accepted calibration.

## 3. Preflight testing

The preflight program uses production calibration but **never changes it**. Every run saves a timestamped JSON report under:

```text
/opt/_RunScanner/TestGyro/preflight/
```

A robot is ready only when the command finishes with `PREFLIGHT PASS`. A failure, cancellation, or error is a stop condition: inspect the JSON report and correct the cause before a long test.

### Mode A — Static-only

Use after startup, software changes, or for a quick non-moving health check:

```bash
python3 TestGyro/robot_mobility_preflight.py --static-only
```

It checks:

- production calibration loads;
- repeated motor-HAT communication;
- stationary gyro stability and agreement with stored bias;
- location/camera pipeline twice;
- both `front.ok=true` and `rear.ok=true` on every camera attempt;
- both `front` and `rear` roles are declared.

Keep the robot completely stationary during the gyro check.

### Mode B — Standard mobility preflight

Use before ordinary mobility work when a bump crossing will not be tested:

```bash
python3 TestGyro/robot_mobility_preflight.py
```

It performs the static checks plus:

1. **Lifted wheel test:** securely lift the robot with all wheels clear; verify all four start immediately and rotate forward together.
2. **0.10-m startup move:** verify immediate start with no hesitation, internal fighting, or abnormal sound.
3. **1.00-m flat-floor move:** enter:
   - measured forward distance in **cm**;
   - final heading error in degrees, where **CCW/left is positive**;
   - lateral displacement in **cm**, where **left is positive**;
   - whether motion was smooth without visible zig-zag or hesitation.
4. **Alternating turns:** four cycles of `+90°` then `-90°`; verify every turn starts smoothly with all wheels engaged and no abnormal sound.
5. Post-motion motor-HAT, stationary-gyro, and dual-camera checks.

Automatic limits for the 1.00-m move are:

- distance: `90–110 cm`
- absolute heading error: no more than `5°`
- absolute lateral displacement: no more than `10 cm`
- smooth-motion answer: yes

### Mode C — Full preflight with bump

Use before an overnight or other time-consuming mobility test involving the ramp:

```bash
python3 TestGyro/robot_mobility_preflight.py --with-bump
```

It performs the complete standard preflight and then:

1. Runs one production-calibrated `2.00 m` inner-to-outer crossing.
2. Runs one production-calibrated `2.00 m` outer-to-inner crossing.
3. For each crossing, enter measured distance in centimetres and confirm that all wheels cleared without stall, fighting, or manual assistance.

Automatic bump-distance limits are `185–215 cm` in each direction.

## 4. Recommended sequence for each upgraded robot

1. Complete the hardware inspection.
2. Run `i2cdetect -y 1` and confirm `10` and `68`.
3. Run the calibration `--check` command.
4. Run the full interactive calibration, calibrating every section for a newly upgraded robot.
5. Run calibration `--check` again.
6. Run static-only preflight.
7. Run standard preflight.
8. Run full preflight with bump.
9. Preserve the calibration result and preflight JSON reports.
10. Proceed to the overnight test only after full preflight passes.

For fleet rollout, upgrade and validate one additional robot first. Keep at least one known-working legacy robot unchanged until the upgraded design has demonstrated repeatability on more than one robot.

## 5. Quick command reference

```bash
cd /opt/_RunScanner

# Confirm I2C devices
i2cdetect -y 1

# Show active calibration; no movement and no changes
python3 TestGyro/robot_mobility_calibrate_v2.py --check

# Interactive calibration
python3 TestGyro/robot_mobility_calibrate_v2.py

# Static health checks only
python3 TestGyro/robot_mobility_preflight.py --static-only

# Standard flat-floor mobility preflight
python3 TestGyro/robot_mobility_preflight.py

# Full preflight including both bump directions
python3 TestGyro/robot_mobility_preflight.py --with-bump
```

## 6. Stop conditions

Stop and investigate instead of continuing when any of these occurs:

- I2C address `10` or `68` is missing.
- Any wheel fails to start immediately.
- A wheel stalls or the robot pivots around one wheel.
- Movement shows repeated hesitation, internal fighting, or abnormal sound.
- Heading control creates visible zig-zag or excessive lateral displacement.
- The robot stalls on the ramp or requires manual assistance.
- Either front or rear camera check fails.
- The preflight ends with anything other than `PREFLIGHT PASS`.
